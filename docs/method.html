Method: a careful way to organize digital files with AI

This is the plain-language method for using AI to understand a messy collection before changing it. It can help with old hard drives, cloud exports, photo libraries, project folders, and backups.

The technical partner is AI-ASSISTED-METHOD.md.

1. Set the question and boundary

Start with one clear question.

Examples:

  • Where are the family photos?
  • Which files are on this old drive?
  • Which copies should I keep?

Write down what you are checking, who may be affected, and what you will not change yet. Do not begin by saying, “Clean everything.” Leave deleting and large renaming jobs for later.

2. Discover before you change anything

Look first. Do not change the original files.

Make a list of:

  • the computer, drive, phone, account, or export;
  • the folder and file name;
  • the file type and size;
  • the dates you can see;
  • whether the file opens; and
  • any problem you notice.

This list is called an inventory. It tells you what was there when you looked. It does not tell you what every file means.

Keep five drives as five separate sources until you record where each file came from. Do not mix them into one folder first.

3. Keep the file history

Write down where each file came from and what happened to it.

Record the original source, path, dates, copies, exports, edits, and related files. This history helps you understand the collection later.

Useful labels include:

  • original;
  • copy;
  • edited copy;
  • export;
  • backup;
  • related; and
  • not sure.

4. Keep facts separate from guesses

A fact is something you can check.

Examples:

  • The file is named photo.jpg.
  • It is 4 MB.
  • It is on Drive 2.
  • It opens successfully.

A guess is an idea that still needs checking.

Examples:

  • This may be the best copy.
  • These photos may be from the same event.
  • This folder may belong to one person.

Mark guesses clearly. Do not let an AI guess become a fact just because it sounds sure.

5. Use more than one way to describe a file

Do not force every file into one perfect folder.

Describe a file in separate ways:

  • where it came from;
  • what project, person, subject, or event it may involve;
  • what kind of file it is;
  • whether it is an original, copy, edit, or export; and
  • how sure you are.

This lets one file belong to several useful groups without making extra copies.

6. Rate confidence and keep uncertainty

Use simple confidence labels:

  • high: the evidence is strong;
  • medium: the idea is likely but needs a check; and
  • low: the idea is only a clue.

Keep an “unknown” label. It is better to say “not sure” than to put a file in the wrong group.

7. Use AI for review, not authority

AI can help you:

  • sort a long inventory;
  • spot repeated names, dates, and sizes;
  • explain file types;
  • suggest group names;
  • find questions to ask; and
  • compare information you provide.

AI cannot know what a memory means to you. It cannot prove who owns a file or decide what is safe to delete.

Share a small, redacted sample. Do not upload a full private archive. Ask the AI to separate facts from guesses and show its reasons.

8. Compare copies and related files carefully

Two files may look alike but have different histories.

Compare:

  • file name and path;
  • size and dates;
  • checksum, when useful;
  • visible content;
  • edits and metadata; and
  • where each copy came from.

A duplicate is not always safe to remove. One copy may have notes, rights, or meaning that another does not.

9. Propose before applying a change

Before changing files, write down a plan.

For each proposed change, record:

  • which files are included;
  • what you want to do;
  • why;
  • what evidence supports it;
  • who approved it; and
  • how you can undo it.

Do not let an AI tool make the final choice. A person must approve deletion, merging, overwriting, bulk renaming, or public sharing.

10. Stage changes so you can undo them

Work in a new folder or on a copy.

Use small batches. Keep an inventory and a simple action log. Put uncertain files in a holding area.

Keep the original source unchanged until you have checked the result. Before using a cloud service’s cleanup or merge tool, save an export or backup first.

11. Verify the result

After a copy or move, check:

  • file and folder counts;
  • a sample of the files;
  • dates and metadata;
  • whether files open; and
  • checksums, when useful.

Write down skipped, failed, changed, missing, or unreadable items.

Run a new inventory after a large move. A task that finishes without an error is not proof that everything is correct.

12. Know when to stop

Stop and keep the current state if:

  • files are missing;
  • checksums changed without a clear reason;
  • a cloud service acts in an unclear way;
  • the AI answer conflicts with what you know; or
  • the choice could affect rights, safety, or another person’s privacy.

Record the problem. Ask the owner or a qualified specialist for help when needed.

13. How this connects to established practice

This method uses ideas from digital preservation, careful file management, archives, and human-supervised AI work.

Inventories help you know what you have. File history helps you know where it came from. Checksums help you check that files did not change. Human review handles choices that file matching cannot solve.

This is a lightweight method for personal work. Larger or more valuable collections may need stronger records and expert help. See REFERENCES.md for sources and SAFETY.md for privacy and backup guidance.
