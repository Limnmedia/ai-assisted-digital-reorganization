# Discoverability and search language

The goal is useful findability, not inflated priority claims or keyword stuffing.

## Suggested GitHub metadata

**Repository name:** `ai-assisted-digital-reorganization`

**Description:** `A practical, safety-first field guide to using AI to inventory, understand, consolidate, and preserve accumulated digital files and photo libraries.`

**Topics:** `artificial-intelligence`, `ai-assisted`, `digital-organization`, `digital-preservation`, `digital-curation`, `personal-information-management`, `digital-archives`, `digital-archaeology`, `file-organization`, `photo-organization`, `provenance`, `human-in-the-loop`

These are recommendations only. They do not authorize creating, renaming, publishing, or changing a GitHub repository.

## Search language to use naturally

Use reader language in headings or explanatory prose where it is accurate: “organize old hard drives with AI,” “AI digital archive organization,” “AI-assisted digital curation,” “consolidate Google Photos safely,” “digital preservation for personal files,” and “human-reviewed file organization.” Do not repeat phrases mechanically, hide text, or imply guaranteed results.

## Publication checklist

- Keep the README concrete and link directly to method, safety, case study, and sources.
- Use descriptive filenames and headings.
- Link primary references directly and record the date checked.
- Add issue templates only when the repository is ready for public maintenance.
- Publish examples and test data only after rights and privacy review.
- Use a stable release or tag when readers need to cite a version.

## Claims policy

Prefer “practical synthesis,” “documented case study,” or “early public guide” when those descriptions are accurate. Do not claim “first,” “proven,” “safe for everyone,” or “works for all files” without a defensible search protocol and evidence. If the practice appears to be emerging during AI adoption, describe that as an open cultural or research question.
